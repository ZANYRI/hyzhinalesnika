## Что реализовано

- Самостоятельное подключение `https://mc.yandex.ru/metrika/tag.js` через Next.js Script после отдельного разрешения аналитики. Счётчик работает только на `https://hyzhinalesnika.ru`; локальные и тестовые домены исключены.
- Для Next.js переходы между страницами фиксируются через `hit`, начальная автоматическая отправка отключена через `defer: true`. Повторный эффект для одного URL не создаёт дополнительный просмотр. UTM, yclid и gclid сохраняются; произвольные параметры и фрагмент URL исключаются из явных вызовов `hit`.
- Вебвизор, карта кликов и автоматический сбор внешних ссылок в подключении выключены. Обрабатываются просмотры и перечисленные ниже целевые события.
- Номер счётчика объявлен один раз в `src/lib/metrica.ts`.
- Удалена отправка полного объекта `onBooking` из Контур.Отеля в Метрику. В событии сохраняется идентификатор цели; имя, телефон, email, состав гостей и содержание брони этим обработчиком не передаются.
- Обе формы сообщают об успешной заявке после HTTP-подтверждения от `/api/contact`. Ошибка сервера, сбой сети и отсутствие согласия на обратный звонок не создают достижение цели.
- Общий обработчик контактов учитывает собственный телефон и профили базы в WhatsApp, Telegram, MAX и Instagram. Номера партнёров и произвольные чужие профили исключены. Клик по контакту сам по себе не подтверждает разговор или отправку сообщения.

## Выбор посетителя

Действующий пункт 8.2 политики обработки персональных данных требует отдельного активного выбора для необязательной аналитики и возможности его изменения. Поэтому прежняя отметка `hyzhina_cookie_notice=seen` не считается согласием на Метрику.

- Компактная плашка предлагает «Разрешить» и «Отклонить» без предварительного выбора.
- Закрытие первой плашки оставляет аналитику выключенной. Закрытие повторно открытых настроек сохраняет ранее принятый выбор.
- Выбор можно изменить кнопкой «Настройки cookie» в футере любой страницы.
- В localStorage `hyzhina_analytics_consent` сохраняются версия `2026-11-09-1`, решение, дата и срок действия до 365 дней. Это локальная настройка браузера; отдельный серверный журнал аналитических согласий не создаётся. При блокировке хранилища выбор действует в текущей вкладке.
- Изменение выбора синхронизируется между открытыми вкладками через `storage`.
- При отказе останавливается собственный счётчик методом `destruct`, отменяются ещё не отправленные команды очереди этого счётчика и удаляются доступные `_ym_` cookie текущего домена. Ранее переданные данные этим действием не удаляются из кабинета сервиса. Cookie сторонних доменов удаляются средствами браузера.
- Отказ не отключает формы и модуль бронирования. Параметры аналитики стороннего SDK Контур.Отеля не менялись.

9 ноября 2026 года владелец согласовал дополнение из `cookie-policy-addendum-draft.md`. Текст внесён в страницу cookie и раздел 4.7 политики обработки персональных данных; дата редакции политики обновлена. Версия `ANALYTICS_CONSENT_VERSION` повышена до `2026-11-09-1`: после публикации посетители повторно выбирают разрешение аналитики. Согласия для заявок и обратного звонка сохранены. Изменения пока локальные; настройки кабинета и фактическая доставка событий требуют проверки.

## Что создать в кабинете

Откройте счётчик **98987390 → Цели → Добавить цель → Целевое событие**. Для каждой цели задайте условие «совпадает» и идентификатор из таблицы. Если цель с таким идентификатором уже есть, используйте существующую.

| Название | Идентификатор | Что означает |
|---|---|---|
| Бронирование через Контур.Отель | `kontur_booking` | Вызов SDK `onBooking`; статус оплаты и доход не передаются |
| Заявка на обратный звонок | `callback_sent` | Сервер успешно принял и доставил заявку из одной из двух форм |
| Нажатие на телефон базы | `phone_click` | Нажатие на основной телефон +7 (928) 020-10-01 |
| Переход в мессенджер | `messenger_click` | Нажатие на контактный профиль базы; параметр `channel` |
| Просмотр страницы бронирования | `booking_page` | Просмотр `/booking`; промежуточное действие |

Для `callback_sent` передаётся только категориальный `form`: `callback` либо `booking_assistance`. Для `messenger_click` передаётся только категориальный `channel`: `whatsapp`, `telegram`, `max` либо `instagram`. Фиктивный доход целям не назначается. Бронирование, обращения и промежуточные действия следует оценивать раздельно.

После согласования текста и деплоя:

1. Откройте `https://hyzhinalesnika.ru/?_ym_debug=2` без блокировщика аналитики.
2. Проверьте отказ: счётчик данного подключения не загружается. Нажмите «Настройки cookie» и разрешите аналитику.
3. В панели отладки проверьте один просмотр главной, затем `/booking`, событие `booking_page`, переход на свой мессенджер и `phone_click`.
4. Проверку настоящей отправки заявки выполняйте осознанно: она уведомляет администратора. В ходе разработки настоящие заявки не отправлялись.
5. Проверку `kontur_booking` проводите при следующем действительном бронировании, без фиктивной оплаты и тестового заказа на рабочем сайте.
6. Повторно откажитесь от аналитики через футер и проверьте остановку отправки событий.
7. В кабинете проверьте накопление визитов и целей. Новый счётчик не добавляйте, номер сохраняется.
