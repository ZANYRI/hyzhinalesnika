## Изменения

- Добавлены семь отдельных JPEG-карточек в `public/images/social/`, размер 1200×630. Использованы существующие фотографии домов и текущее лого. Юридические тексты, условия и цены не менялись.
- В `social-previews.json` добавлены соответствующие страницы; путь `/consents` служит общим правилом для текущей и архивных версий согласий. Для неизвестных страниц сохранена запасная карточка бренда.
- `social-image-versions.json` содержит SHA-256 версии файлов. В `og:image` и `twitter:image` добавлен параметр `v` с первыми 12 символами хеша. URL меняется при изменении содержимого изображения. URL самих страниц, canonical и sitemap сохранены.
- Добавлен `og:image:secure_url`. OG и Twitter используют одну и ту же абсолютную HTTPS-ссылку.
- Генератор поддерживает `--social-only` для сохранения текущих favicon и `--only` для выборочного обновления карточек. Существующие 13 JPEG и все файлы favicon оставлены без изменений.
- Добавлена команда `npm run test:social`, проверяющая серверные метатеги в `<head>` для TelegramBot и WhatsApp, индивидуальность карточек, доступность файлов, размер JPEG, соответствие хешей и единый favicon на всех страницах.

Команда для воспроизведения новых карточек:

```sh
node scripts/generate-brand-assets.mjs --social-only --only /otdyh-s-zhivotnymi,/cookie-policy,/privacy-policy,/oferta,/users/agreement,/consents,/search
```

Генератор использует установленные зависимости Next.js и существующий механизм `ImageResponse`. Для шрифтов применяются прежние параметры `SOCIAL_FONT_REGULAR` / `SOCIAL_FONT_BOLD`; без них используются существующие стандартные пути Arial в macOS. Генерация выполняется заранее, файлы входят в Git, сборка сервера не требует этих системных шрифтов.

## Ограничения и дальнейшие действия

1. После согласованного деплоя повторить `test:social` на рабочем домене.
2. Проверить конкретную ссылку и сервис, где владелец видит отсутствие превью или иконки. Смена версии изображения не принуждает сервис немедленно обновить уже сохранённый HTML-просмотр ссылки.
3. Общий favicon продолжает использовать текущее лого. Google применяет один favicon на hostname и самостоятельно обрабатывает обновления; наличие корректного файла не гарантирует показ у каждого результата поиска. Источник: https://developers.google.com/search/docs/appearance/favicon-in-search . Стабильные адреса иконок сохранены.

Уверенность высокая в доступности метатегов и файлов и в результатах локальных проверок. Причина отсутствующего отображения у владельца пока не установлена: конкретный URL и приложение ещё не указаны.
