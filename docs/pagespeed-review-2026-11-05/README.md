## Подтверждённые замечания и приоритет

1. **P2: работа виджета после первоначальной отрисовки /booking.** LCP здесь соответствует вводному тексту. Его 0,93 с не измеряют готовность календаря и выбора дома. TBT составляет 290 мс, диагностический Time to Interactive — около 9,2 с. У widget.js есть задачи длительностью 353, 145 и 108 мс. Из 420 КиБ потенциально неиспользуемого JavaScript около 394 КиБ приходится на этот файл. Следующее направление — согласованная с поставщиком оптимизация загрузки/инициализации и проверка готовности календаря на реальном мобильном устройстве. Произвольное удаление частей SDK и откладывание календаря до клика не выполнялись.

2. **P2: сторонние cookie /booking.** Оба проваленных аудита категории рекомендаций относятся к Cookie: ngtoken, https://metrika.kontur.ru/static/js/cds.html. Это источник оценки 77 в данном отчёте. Сетевой источник подтверждён. Из этого отчёта нельзя делать вывод о назначении cookie или о юридическом соответствии. Требуется документированная настройка поставщика. Блокировка метрики или домена и вмешательство в согласия без дополнительной проверки не выполнялись.

3. **P3: кэш и размеры ресурсов поставщика.** PageSpeed оценивает потенциальную экономию кэша в 806 КиБ: widget.js (816545 байт передачи) и три SVG с bookonline24.ru имеют cacheLifetimeMs=0. Для SVG кроватей DoubleKing, Single, Double не заданы явные размеры. Заголовки внешнего домена из Next.js изменить нельзя. Следует запросить поддержку версионированного SDK и кэширования, а размеры согласовать с реальной вёрсткой виджета. Оценки экономии разных аудитов перекрываются; суммировать их нельзя.

4. **P3: доступное название ссылки «Сплит» на главной.** В отчёте есть label-content-name-mismatch, несмотря на итоговые 100 за доступность. Видимая надпись «Я Сплит» расходится с переопределением aria-label «Яндекс Сплит: оплата отдыха частями». Замечание воспроизведено axe-core 4.14.0 в браузере. Локально убран переопределяющий aria-label; имя ссылки формируется из её содержимого «Сплит», декоративный логотип сохраняет aria-hidden. Дизайн, адрес /split и условия оплаты сохранены.

## Главная: обнаружение LCP

PageSpeed подтверждает eager-загрузку, fetchpriority=high и обнаружение в исходном HTML. Запрос portrait AVIF действительно является preload, priority High, 56717 байт содержимого. Повторного запроса hero-bg в исходном отчёте нет.

Наблюдаемый разбор: TTFB около 250 мс, задержка начала ресурса около 1578 мс, скачивание около 122 мс, отрисовка около 212 мс. HTML-документ завершился около 1816 мс; preload начал запрашиваться около 1828 мс. Поэтому большой интервал связан с получением/обнаружением HTML в этом запуске; его точную причину (передача, буферизация, серверный путь) один отчёт не доказывает. Дополнительное сжатие уже небольшого AVIF или ещё один preload не обоснованы этими данными. Для дальнейшего снижения LCP нужен отдельный анализ потока HTML и серверных заголовков.
